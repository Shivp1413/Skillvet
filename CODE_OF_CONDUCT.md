# Code of conduct

## The short version

Be decent. Assume good faith, critique the code and not the person, and remember
that most people here are volunteering their evenings.

## Expected behaviour

- Give and accept technical criticism gracefully. "This rule will false-positive
  on X, here is the snippet" is a gift.
- Be specific about what would change your mind.
- Respect that reviewers' time is the scarce resource here: a focused pull
  request with tests gets merged far faster than a large one without.
- Use welcoming, plain language. Not everyone's first language is English, and
  nobody's first draft is perfect.

## Unacceptable behaviour

- Harassment, insults, or personal attacks of any kind.
- Discriminatory jokes or language.
- Publishing someone's private information without permission.
- Sustained disruption of discussions or deliberate bad-faith argument.
- Using this project's issue tracker to publish a working exploit against a
  real person, skill author or package. Report it privately per SECURITY.md.

## Scope

This applies to issues, pull requests, discussions and any other project space,
and to any situation where you are representing the project in public.

## Enforcement

Report a problem to the maintainers through a private security advisory or by
email to the address listed on the repository profile. Reports are read by the
maintainers only, and are handled confidentially.

Responses escalate with severity and repetition:

1. A private word, and a request to change the behaviour.
2. A public warning, and removal of the offending content.
3. A temporary ban from project spaces.
4. A permanent ban.

Maintainers who do not follow this code will face the same consequences as
anyone else.
